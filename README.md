1. Objective
	The goal of this project was to understand how an SSH brute-force attack works from both the attacker 	
	and defender perspectives in a controlled environment. 
	Ubuntu Server 24.04 and Kali Linux 	
	were deployed using QEMU/KVM. I also wanted to learn how Wazuh SIEM detects and classifies security 	
	events generated by another system.
	
	
2. Detection and Log analysis.
	While monitoring Wazuh SIEM and the Ubuntu authentication logs, I observed multiple SSH login attempts 	
	coming from the same source IP address. After analyzing these events, I found that Wazuh classified the 	
	activity as brute-force/password-guessing behavior and mapped it to the corresponding MITRE ATT&CK 	
	technique. The repeated attempts were targeting the SSH service on port 22. 
	 
	First authentication Log Analysis was in live mode when I read in auth.log. I observed multiple 	
	requests/attempts to log in trough connection port 22 ssh. Getting a more request I understand that's 	
	brute force attack from IP-address 192.168.122.210. (Kali Linux IP). Wazuh collecting a log's and I can
	a read rule.id when trying initial access.


3. Reconnaissance && Attack Simulation
	I started by scanning the local network to identify the Ubuntu Server and determine its IP address. 
	After locating the target, I used Nmap to enumerate open ports and identify exposed services. The scan 	
	showed that SSH was available on port 22, which became the main service used for the controlled 	
	authentication test.
	After identifying the SSH service, I generated repeated failed authentication attempts from the Kali 
	Linux machine to the Ubuntu Server. The goal was to simulate password-guessing activity in a
	controlled environment and observe how the target system and Wazuh responded to it.

4. Mitigation
	To reduce the risk of repeated SSH authentication attempts, I configured Fail2ban to monitor the SSH 	
	service and automatically block IP addresses that exceed the configured authentication failure
	threshold.
	The `sshd` jail was configured with:
	- `maxretry = 5`
	- `findtime = 600 seconds`
	- `bantime = 600 seconds`

	During verification, the Kali Linux IP address `192.168.122.210` was successfully added to the Fail2ban
	banned IP list after repeated failed SSH login attempts.

5. Learning outcomes
	During this project, I learned how to identify repeated SSH authentication attempts, analyze Linux
	authentication logs, investigate Wazuh alerts and rule IDs, review JSON event data, and understand how
	Fail2ban can respond to repeated failed login attempts. I also improved my understanding of how
	attacker activity can be observed from the defender side.
